# Obsidian 报告生成规范

从任务记录生成工作报告。报告与任务放在同一年度目录，每次生成插入到对应报告文件头部，最新在最上面。

## 目录

- 数据模型、报告文件、写入冲突与日期范围
- 状态映射
- 日报、周报、月报、季度报告
- 半年、全年和任意日期范围工作总结
- 质量要求

## 数据模型

- 任务文件：`任务/{YYYY}/计划中.md`；归档文件：`任务/{YYYY}/已归档.md`。
- 任务按 `## 项目名` 分区，任务行是 checkbox；父任务为顶层 checkbox，子任务每层 1 Tab 缩进。

## 报告文件

| 报告 | 文件 |
| --- | --- |
| 日报 | `任务/{YYYY}/日报.md` |
| 周报 | `任务/{YYYY}/周报.md` |
| 月报 | `任务/{YYYY}/月报.md` |
| 季度报告 | `任务/{YYYY}/季度报告.md` |
| 年度报告-半年 | `任务/{YYYY}/半年报.md` |
| 年度报告-全年 | `任务/{YYYY}/年度报告.md` |
| 任意日期范围 | `任务/{结束年份}/工作总结.md` |

写入规则：

- 文件不存在时创建并写总标题：`# {YYYY} 日报`、`# {YYYY} 周报` 等。
- 文件存在时保留第一行总标题，新报告插入到总标题下面，最新在最上面。
- 同一周期已有报告时，不直接重复写入。先回显已有标题与拟生成范围，让用户选择新增一版、替换该周期或仅预览。

## 写入冲突与预览

- 目标周期不存在：可以直接创建或在总标题下新增。
- `新增一版`：保留已有段落，在头部插入新段落。
- `替换该周期`：只替换标题完全匹配的报告段落；写入前展示摘要并确认，不覆盖其他周期。
- `仅预览`：只在聊天中展示候选正文，不写文件。
- `候选版`：仅当用户明确要求保存候选时，在标题后加 `（候选）` 写入；确认转正后再替换正式段落。

## 日期范围

| 报告 | 范围 |
| --- | --- |
| 日报 | 指定日期，默认今天 |
| 周报 | 指定日期所在工作周，周一到周五 |
| 月报 | 指定月份 |
| 季度报告 | `YYYY-Q1`…`YYYY-Q4` |
| 年度报告-半年 | `YYYY-H1` 或 `YYYY-H2` |
| 年度报告-全年 | 指定年份 |
| 任意日期范围 | 明确的开始日期与结束日期，含首尾两天 |

筛选规则：

- 日期范围跨多年时读取多个年度目录。
- 日报只纳入 `🛫 <= 报告日期 <= 📅` 的任务。
- 周报及以上纳入范围内开始、计划完成、实际完成或持续中的任务。
- 任务已归档但 `✅` 或任务周期落在报告范围内时必须纳入。
- 任意日期范围按区间相交筛选：`🛫 <= 范围结束` 且 `📅 >= 范围开始`，或 `✅` 落在范围内。

## 状态映射

| 标记 | 报告状态 |
| --- | --- |
| `[x]` | 已完成 |
| `[/]` | 进行中 |
| `[?]` | 阻塞 |
| `[ ]` | 未开始 |

- 完成日期来自 `✅`，计划完成来自 `📅`，开始来自 `🛫`。
- 备注来自任务下方缩进 blockquote（`> ...`）；兼容读取历史普通列表行注释与行尾 `备注：...`。

## 日报格式

日报是**最短**的报告，只回答「今天做了哪几件事、进展如何」。不显示日期、不做表格、不写长段总结、不写背景原因。

```markdown
## 2026-06-22 日报

【数据任务】基础依赖解析组件开发：当前使用 a 技术解决，目前进行中
【系统管理】报告技能重构：已确认日报与周报格式
```

- 项目按项目名排序。每条优先合并同项目、同父任务或同类工作的子任务；父任务无子任务时把父任务当一条。
- 格式固定：`【项目名】子任务标题：描述`。描述优先来自备注，没有则用状态和上下文生成一句简短说明。
- **硬性字数控制**：
  - 日报**最多 5 条**；超过 5 条时只保留当天最相关的 5 条，其余合并或省略。
  - 每条描述**只写一句**、**≤ 35 个汉字**；超长时删背景、原因、日期和修饰词，只留「动作 + 结果 / 状态」。
  - 日报正文（不含标题）**总字数 ≤ 200 字**。
  - **禁止**写「背景说明」「原因分析」「下一步计划」段落——这些属于周报及以上。
- 不显示 `🛫` / `📅` / `✅` 日期，不输出未落在当天周期内的任务。
## 2026-06-22 日报

【数据任务】基础依赖解析组件开发：当前使用 a 技术解决，目前进行中
【系统管理】报告技能重构：已确认日报与周报格式
```

- 项目按项目名排序。每条优先合并同项目、同父任务或同类工作的子任务；父任务无子任务时把父任务当一条。
- 格式固定：`【项目名】子任务标题：描述`。描述优先来自备注，没有则用状态和上下文生成一句简短说明。
- 描述是一句短句，单条 20-35 汉字左右，日报一般 3-5 条。不显示日期，不输出未落在当天周期内的任务。

## 周报格式

正式格式使用 AnyBlock 插件的 `[list2table]` 渲染三列表格：`项目 | 任务 | 完成情况`（表头固定不变），保留表格观感；源码是紧凑列表，行按状态分组、跨项目合并，解决 HTML 表格行高过高与已完成任务碎片化问题。依赖 Obsidian 社区插件 **AnyBlock**（`any-block`）；未安装时表格不渲染，但源码仍是可读的紧凑列表，不影响内容。

```markdown
## 2026-08-17 ~ 2026-08-21 周报

[list2table]
- < 项目| 任务| 完成情况
- 联盟DSP
  - **【已完成】** 框架契约主导化重构、领域能力归位、openspec 1.9 升级、文档收敛、部署脚本治理、Aerospike IDC 路由；throw/newrd 接口迁移、分包修正与 parity 门禁修复 | 框架治理与接口迁移落地，parity 门禁修复闭环
  - **【进行中】** 联盟服务统一 Go 框架持续升级；PC/移动业务迁移推进中 | 迁移推进中，按计划进行
  - **【后续安排】** 继续剩余业务接口迁移与框架升级收尾 | 下周完成迁移收尾
- 导航联盟
  - **【已完成】** 年中内审材料清单第一版交付；un-navigation-specs 统一切换公司组件并落地 DSH 开发适配 | 材料交付与标准化底座落地
  - **【进行中】** un-navigation-specs AI 自动化需求流程开发 | 需求评审待完成
  - **【后续安排】** 按内审反馈迭代材料，基于标准化底座推进后续开发 | 迭代材料并推进流程开发
```

生成规则：

- 标题用工作周范围：`## YYYY-MM-DD ~ YYYY-MM-DD 周报`（通常周一到周五）；标题下不再单独写时间范围行。
- 依赖 AnyBlock：`[list2table]` 独占一行；表头用 `- < 项目| 任务| 完成情况`；顶级列表项是项目（项目列自动合并），缩进子项是数据行，`|` 分列。
- 日报和周报默认只读 `计划中.md`，不扫 `已归档.md`，避免部分归档父任务重复统计。
- 不统计 `[ ]` 未开始任务。扫描范围同时考虑完成时间和规划时间：`✅` 落在本周，或计划区间与本周有交集（`🛫 <= 周五` 且 `📅 >= 周一`）即纳入。
- 行按状态分组，每项目最多四行、顺序固定：`【已完成】` → `【进行中】` → `【阻塞】` → `【后续安排】`。状态映射：`[x]`→已完成、`[/]`→进行中、`[?]`→阻塞；`[ ]` 不纳入。无内容的行省略。
- 任务列 = `**【状态】**` + 该项目在本状态下的合并说明：多个父任务 / 子任务组用 `；` 串联关键项，子任务多时只保留关键子任务标题，不逐条罗列。
- 同一项目既有已完成子任务又有进行中的父任务时，已完成子任务归 `【已完成】` 行，父任务归 `【进行中】` 行，两处不重复内容。
- 同一任务带多个 `#project/` 标签时只归入首个项目，不重复出现。
- 完成情况列写该状态组的总体概括（一句到两句）：已完成写结果，进行中写进展，阻塞写等待事项，后续安排写下周方向。不逐条复制任务列。
- 单元格内用纯文本 + `；` 串联，不用 HTML `<ul><li>`（避免行高过高）；单元格内容不要包含 `|`。
- 进行中行保留进度标注：`【进行中：NN%】` 或 `【进行中：计划YYYY-MM-DD】`。百分比只能来自任务记录或用户明确给出，不推算。
- 明细只能来自任务标题、说明、子任务、状态和日期关系；不编造完成结果、比例、指标或依赖方。
- 表格内项目按项目名排序。

### 周报测试规则

- 测试阶段先用增加模式生成候选周报，不覆盖已有正式段落。用户确认后才替换正式周报或删旧候选。

## 月报格式

```markdown
## 2026-06 月报

### 项目A

- 主要完成：
  - 任务一：基于任务记录归纳成果
- 持续推进：
  - 任务二：说明当前进展
- 问题与风险：
  - 任务三：说明阻塞或待确认事项
- 下月关注：
  - 从未完成、进行中和后续计划任务中归纳
```

## 季度报告格式

只用于 `Q1/Q2/Q3/Q4`，写入 `任务/{YYYY}/季度报告.md`。材料化结构，不用表格，按项目分段。

```markdown
## 2026-Q2 季度报告

### 项目A

- 围绕业务贡献总结季度完成内容，把可衡量指标融入描述（完成任务数、验证规模、接口量、问题修复数）。
- 说明仍在推进或需下季度关注的事项。

### 下季度规划

- 按方向写目标、重点工作、预期贡献和建议跟踪指标。
```

- 标题 `## YYYY-QN 季度报告`；周期只能是 Q1-Q4。必须按项目归纳，不逐条罗列。
- 指标必须来自任务记录或用户提供，融入描述，不单独列"指标清单"。不编造比例、收益、数量。

## 年度报告格式

半年报告写 `任务/{YYYY}/半年报.md`，全年报告写 `任务/{YYYY}/年度报告.md`。按项目归纳，材料化要点风格，不写流水账。

### 半年报告

```markdown
## 2026-H1 半年报告

### 一、项目A

- **核心方向：**
  - 材料风格总结重点工作，融合可参考指标。
- **业务贡献：**
  - 说明对业务稳定 / 迁移效率 / 数据质量 / 平台能力的支撑。
- **不足与后续：**
  - 说明未闭环事项和下半年改进方向。

### 亮点、不足以及改进计划

- **亮点：** …
- **不足：** …
- **改进计划：** …
```

- 标题 `## YYYY-H1 半年报告` 或 `H2`。按项目分段，"编号标题 + 粗体小项 + 嵌套要点"。用户要求字数时严格按上下限。指标融入正文。

### 全年报告

```markdown
## 2026 全年报告

### 项目A

- 年度成果：基于已完成任务归纳
- 建设与支撑：基于父子任务层级归纳
- 问题与风险：基于阻塞和待确认任务归纳

### 下一年度计划

- 从未完成任务和后续计划中整理
```

- 标题 `## YYYY 全年报告`。按项目归纳全年成果、建设支撑、问题风险和下一年度计划。用户只给 `H1/H2` 时应生成半年报告。

## 任意日期范围工作总结

写入 `任务/{结束年份}/工作总结.md`；跨年时读取涉及的所有年度目录，但只生成一个范围段落。

```markdown
## 2026-06-15 ~ 2026-07-15 工作总结

### 项目A

- 已完成：基于 `[x]` 和范围内 `✅` 归纳。
- 持续推进：基于 `[/]` 及与范围相交的计划周期归纳。
- 阻塞与风险：基于 `[?]` 和备注归纳。
- 后续关注：基于未完成任务的计划日期归纳。
```

- 开始日期不得晚于结束日期；缺任一日期时先确认。
- 默认按项目分组，保留父子上下文，不把同一任务同时重复写入多个状态小节。
- 标题固定为 `## YYYY-MM-DD ~ YYYY-MM-DD 工作总结`，用于同范围冲突检测。
- 如果用户只要求在聊天中总结，采用仅预览，不创建 `工作总结.md`。

## 质量要求

- 日报短、直观；周报具体、可读；月报及以上按项目归纳，不堆砌全部任务。
- 不编造任务、完成日期、结果、指标或进度百分比。任务记录没有量化指标就不写。
- 任务描述缺失时，允许用父任务、项目和状态补足上下文，但不改变事实。
