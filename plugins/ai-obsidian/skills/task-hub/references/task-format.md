# Obsidian 任务格式契约

task-hub 的创建 / 修改 / 归档 / 报告都读写同一份记录，格式必须逐字一致，否则跨操作查找、筛选、统计会失配。

## 目录

- 任务库位置、文件组织与项目集合
- 任务行格式与旧格式兼容
- 注释与状态
- 子任务、归档、查找和匹配

## 任务库位置

- 默认根路径：当前项目根目录。用户显式指定路径时以用户指定为准。
- 任务根目录：`<项目根目录>/任务`
- 年度目录：`<项目根目录>/任务/{YYYY}`
- 计划文件：`<项目根目录>/任务/{YYYY}/计划中.md`
- 归档文件：`<项目根目录>/任务/{YYYY}/已归档.md`
- 年份按任务开始日期 `🛫` 所在年份确定；跨年查询读取多个年度目录。

## 文件组织

每个任务文件按项目分区：

```markdown
# 2026 计划中任务

## 项目A

- [ ] 父任务 🛫 2026-06-22 📅 2026-06-30^[父任务说明]
	- [ ] 子任务一 🛫 2026-06-22 📅 2026-06-24
	- [/] 子任务二 🛫 2026-06-24 📅 2026-06-27^[子任务二说明]

## 项目B

- [?] 等待确认的任务 🛫 2026-06-20 📅 2026-06-25^[等待接口确认]
```

- 缺少年度目录或文件时可以创建。创建时保留一级标题：`# {YYYY} 计划中任务` 或 `# {YYYY} 已归档任务`。
- 项目分区不存在时，在文件末尾追加 `## 项目名`。
- 同一项目内保留父子层级；不要把子任务移动成顶层任务。

## 项目集合（操作前先扫描，不写死）

项目分区不是预置白名单。每次涉及项目的操作（新增任务、移动/调整项目、按项目筛选、生成报告）前，先扫描当前任务库 `任务/{YYYY}/计划中.md`、`已归档.md` 中已存在的 `## 项目名` 分区，得到当前允许的项目集合。

- 命中已有分区时直接归入。
- 用户给出的项目名不在已有集合内时，先确认再写入：是要**新建分区**，还是某个已有项目的**别名 / 笔误 / 历史叫法**（大小写、简称等）需归一化到已有名——避免产生重复分区。
- 不要自行臆造或静默新增项目分区；也不要预设任何具体项目名或固定映射。

## 任务内容写作

- 任务标题只写一个可执行结果，优先使用「动作 + 对象」或「对象 + 目标」；不要把对话原文、日期、状态、测试日志、项目路径或“用户要求”塞进标题。
- 任务说明 / 备注只保留能帮助后续执行或复盘的事实（范围、约束、结果、证据）；不复制长篇 transcript、Assistant 总结或未经确认的推测。
- 用户给出长段背景时，压缩背景到备注，保留用户的领域名词和明确目标，不擅自改写任务意图。
- 只有多个事项彼此独立、可分别安排日期或状态时才拆成多个任务；同一模块的连续动作使用一个父任务 + 子任务。单一事项直接写叶子任务。
- 从扫描交接创建任务时，标题只能来自 handoff 的工作主线；证据摘要写入备注，不重新从自由文本报告猜任务。
- 新建任务或重写内容后，先检查标题是否为单一结果、备注是否只含事实，再检查状态、日期和项目是否分别落在结构化字段中。

## 任务行格式

```markdown
- [状态] 任务标题 优先级 🛫 YYYY-MM-DD 📅 YYYY-MM-DD ✅ YYYY-MM-DD^[可选说明]
```

- 必填：任务标题、项目（靠所在 `## 项目名` 分区归属，任务行不带项目标签）、开始日期 `🛫`、计划完成日期 `📅`。
- 可选：优先级、完成日期 `✅`、说明 / 备注。
- checkbox 任务行只放任务标题、优先级、循环标记和日期等结构化字段。
- 说明 / 备注写在任务行尾的内联脚注（`^[说明文字]`），紧跟在日期字段之后、无空格分隔；渲染时显示为「上标角标」，不污染正文（见「注释样式」）。

## 旧格式兼容

旧任务格式记录仍可读取和修改：

```markdown
- [/] 任务标题 #project/项目A 🔼 🛫 2026-06-22 📅 2026-06-30
	- 旧格式说明
```

- 项目仍以所在 `## 项目名` 分区为主；`#project/项目名` 作为旧格式一致性字段，不算入标题。
- 普通查看和报告同时读取旧普通列表说明、旧 blockquote 说明与历史行尾 `备注：...`。
- 普通修改保持当前任务树的格式：旧树继续保留标签和说明风格，canonical 树继续使用无标签 + 行尾内联脚注 `^[...]`。
- 旧标签与分区冲突时只报告，不自动改；移动旧任务树时同步更新全部后代标签。
- 完整转换只通过 `legacy-migration.md` 且必须经用户确认。

## 注释样式

注释（说明 / 备注）写在**任务行尾的内联脚注** `^[说明文字]`，**不是 checkbox，也不是独立行 blockquote**。写错会导致注释丢失、层级错乱：

| 行类型 | 写法 | 作用 |
| --- | --- | --- |
| 任务 | `- [ ]` / `- [/]` 等 checkbox | 任务本身 |
| 注释 | `^[说明文字]`（任务行尾内联脚注） | 说明 / 备注 |
| 普通列表项 | `- 文本`（无 checkbox） | **禁止**用作注释 |

- **位置**：内联脚注紧跟任务行尾，紧贴在最后一个日期字段之后、**无空格**（`✅ 2026-08-17^[说明]`）。
- **多行注释**：合并为单个内联脚注，或用句号分隔的连续文字；不要拆成多行。
- **禁用 blockquote**：任务下方缩进的 `> ` blockquote 在 Obsidian 阅读视图下不渲染（连框带文字彻底消失），已废弃。
- 渲染时内联脚注显示为「上标角标」，正文干净、零 HTML、零插件；可安装技能附带的 `任务样式.css` 弱化角标与任务状态着色。

正确示例：

```markdown
- [ ] 父任务 🛫 2026-06-22 📅 2026-06-30^[父任务说明]
	- [ ] 子任务一 🛫 2026-06-22 📅 2026-06-24
	- [/] 子任务二 🛫 2026-06-24 📅 2026-06-27^[子任务二的说明]
```

错误示例（把注释写成 blockquote，会在阅读视图消失；写成普通列表项会让子任务退化成无 checkbox 的列表，破坏层级）：

```markdown
- [ ] 父任务 🛫 2026-06-22 📅 2026-06-30
	> 父任务说明
	- [ ] 子任务一 🛫 2026-06-22 📅 2026-06-24
```

- **写后核验**：新增 / 修改注释后重新读取该任务树，确认注释以 `^[...]` 形式紧贴任务行尾、checkbox 子任务数量与层级未变；发现 `> ` 或 `- 文本` 被当成注释时立即改回 `^[...]`。
## 状态标记

| 标记 | 含义 |
| --- | --- |
| `[ ]` | 未开始 / 未完成 |
| `[/]` | 进行中 |
| `[?]` | 阻塞 / 待确认 |
| `[x]` | 已完成 |

- 新建任务默认 `[ ]`。完成时改 `[x]` 并补 `✅ YYYY-MM-DD`。完成不自动归档。
- 完成子任务后，同一父任务下 checkbox 子任务全部完成时，可自动同步完成父任务，父任务完成日期取子任务中最晚的 `✅`。
- 循环 / 长期支持 / 持续进行类父任务不自动同步完成，除非用户明确要求。
- 手动完成父任务但存在未完成子任务时，先提醒并确认。

## 任务划分（何时用父任务）

- 同一模块/目标的多个相关事项，归组为一个父任务 + 多个子任务；不用「项目分区」当分组单位（同分区下不同模块/目标仍分开）。
- 单一事项作叶子任务，不硬套只有一个子任务的空父任务。
- 父任务标题用模块/目标名（如「sync-ai-session-mcp 迭代」），子任务写具体动作；不用动词堆叠或日期当父任务标题。
- 从 session-scan 等扫描交接时，按其「工作主线」归组：每条主线 = 一个父任务候选，主线内事项 = 子任务；主线只有 1 个事项时作叶子任务。
- 归组前先扫任务库：已存在同模块父任务时并入，不重复新建。
- 分区内可设「类别父任务」（如 ai基础开发 / ai扩展开发 / ai工具开发）做持续分类容器：状态固定 `[/]`，不写 🛫/📅/✅，不自动同步完成；新任务归组时优先归入对应类别，类别不存在时才平铺到分区。
- 类别父任务是**组织容器，不是可排期任务**：仅将状态为 `[/]` 且无 `🛫`、`📅`、`✅` 的 checkbox 行识别为类别容器；其他无日期任务按格式异常处理，不静默隐藏。除非用户明确要求维护分类，否则不创建、不给它补日期、不修改为 `[x]`，也不计入任务数量、日报或周报。
- 报告或筛选命中类别容器时，只沿其父子树读取真实 checkbox 任务；容器标题最多作为内部上下文，不得单独输出为任务条目。

## 子任务规则

- 每层缩进用 1 个 Tab，不用空格。父子任务都用 checkbox。
- checkbox 行是任务；任务行尾 `^[...]` 内联脚注是说明 / 备注（不用 blockquote）。
- 子任务随父任务归入同一 `## 项目名` 分区，不带项目标签。
- 调整项目 = 把任务整棵移到目标 `## 项目名` 分区，子任务随父任务一起移动。

## 归档规则

- 归档必须由用户明确触发（"归档这个任务""归档项目A已完成任务""归档上周完成任务"）。
- 归档时从 `计划中.md` 移动到同年度 `已归档.md`；恢复时移回并按用户要求设置状态。
- 父任务已完成时，归档默认移动整个任务树。
- 父任务未完成但部分子任务已完成时执行部分归档：`计划中.md` 保留父任务和未完成子任务，`已归档.md` 写入同一父任务作为上下文容器、只放已完成子任务。部分归档的父任务保留真实状态，不补 `✅`。
- 恢复父任务或部分子任务前必须确认恢复范围。

## 查找和匹配

- 先按用户给出的项目、标题、父任务、日期范围缩小候选。
- 标题不唯一时不直接修改，要求补充项目、日期或父任务。
- 查看默认读当前年度 `计划中.md`；要历史 / 已完成 / 归档 / 跨年时同时读相关年度 `已归档.md`。
- 日期范围筛选同时考虑 `🛫`、`📅`、`✅`，保留父子层级。
- 标题匹配前剥离旧项目标签、优先级和日期字段。
