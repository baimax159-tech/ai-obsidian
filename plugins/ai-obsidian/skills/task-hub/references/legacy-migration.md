# 旧任务格式迁移

仅在用户明确要求“迁移旧任务格式”“统一为 task-hub 格式”等操作时使用。普通创建、查看、修改和报告不得自动触发全库迁移。

## 旧格式识别

- checkbox 行包含 `#project/项目名`；
- 说明使用缩进普通列表行而不是 blockquote；
- 任务事实、状态和日期仍以 checkbox、`🛫`、`📅`、`✅` 为准。

## 迁移预检

1. 确认任务库根路径、年度范围和是否包含 `已归档.md`。
2. 只读扫描并报告：涉及文件、项目、任务树数量、项目标签数量和旧备注数量。
3. 检查项目标签与所在 `## 项目名` 是否一致；冲突项单独列出并要求用户决定，不自动选边。
4. 默认建议备份。备份位置为 `任务/.task-hub-backup/{YYYYMMDD-HHMMSS}/`，保持原年度目录结构。
5. 展示最小前后示例和准确写入范围，使用宿主原生确认方式取得迁移授权。用户拒绝备份时必须明确确认“无备份继续”。

## 转换规则

- 删除与所在分区一致的 `#project/项目名`；冲突标签按用户选择处理。
- 把任务下属的缩进普通列表说明改为同级缩进 blockquote；checkbox 子任务保持不变。
- 不改变标题、状态、优先级、`🛫`、`📅`、`✅`、父子层级、项目分区或文件归档位置。
- 不合并同名任务，不补缺失日期，不自动完成或归档任务。

## 写入与核验

1. 用户确认后先写备份，再逐文件迁移。
2. 每个文件写完后重新读取，确认 checkbox 数量、任务层级和日期字段数量未减少。
3. 输出已迁移文件、跳过项、冲突项和备份路径。
4. 任一文件核验失败时停止后续写入，报告已完成范围；不要删除备份。
