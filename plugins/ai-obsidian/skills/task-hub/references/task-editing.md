# 任务修改流程

所有修改先定位、预览、确认，再写入。任务格式、状态和旧格式兼容见 `task-format.md`。

## 定位协议

### 1. 缩小候选

优先使用项目、标题、父任务和日期。项目存在时只搜索对应 `## 项目名` 分区；只给标题时全库搜索。

标题比较前剥离：

- `<span class="tp">…</span>` 进度条；
- 旧 `#project/项目名` 标签；
- 优先级符号与 `🛫`、`📅`、`✅` 日期字段。

### 2. 按命中数分流

| 命中数 | 处理 |
| --- | --- |
| 0 | 报告扫描范围，并列出同项目相近标题 |
| 1 | 进入预览确认 |
| 多条 | 用宿主原生交互方式让用户补项目、日期、父任务或直接选行 |

### 3. 回显并确认

回显项目、文件、父任务上下文、原始任务行和拟修改结果。移动或结构修改还要回显整棵任务。用户确认后才写；行不对立即停止。

## A. 状态、日期与优先级

支持：

- `[ ]`、`[/]`、`[?]`、`[x]` 状态切换；
- `🛫` 开始、`📅` 计划完成、`✅` 实际完成日期；
- `⏫`、`🔺`、`🔼`、`🔽` 优先级的新增、替换或移除。

规则：

1. 改为 `[x]` 时补 `✅`；用户未给完成日期时使用当前本地日期。
2. 从 `[x]` 重新打开时默认移除 `✅`；用户要求保留历史时，把原完成日期写入备注，不让结构化字段继续表示已完成。
3. 完成子任务后，若同父全部完成，提示可同步完成父任务；循环、长期支持和持续性父任务除外。
4. 手动完成仍有未完成子任务的父任务时，列出未完成数量并确认。
5. canonical 父任务或已有进度条的父任务在子任务状态变化后必须重算进度条；按已加载的 `task-format.md` 同时写状态 class 和内联主题色，不保留 class-only 色块。旧格式且无进度条的任务树不因普通状态修改被静默升级。

## B. 重命名标题

只替换标题片段，保留状态、旧项目标签、优先级、日期、进度条和下属内容。新标题为空、与同项目同父任务下现有标题冲突或包含 checkbox/日期控制字段时停止确认。

## C. 修改备注

支持添加、替换和删除备注：

- canonical 任务使用所属任务下方一层缩进的 `> ` blockquote；
- 旧任务树保留原有缩进普通列表备注风格；
- 备注操作不修改 checkbox 子任务；删除时只删用户确认的备注行。

如果同一任务有多条备注，先回显编号并让用户选择替换/删除目标。

## D. 移动项目

1. 扫描目标项目集合；未知项目先确认新建或归一化。
2. 移动父任务、全部后代和各自备注，缩进原样保留。
3. canonical 任务不添加项目标签；旧任务树要把所有 checkbox 行的 `#project/旧项目` 同步改为 `#project/新项目`。
4. 回显源分区删除块和目标分区新增块，确认后写入两侧。

## E. 修改父子结构

支持新增、删除、拆分和合并子任务：

1. 新子任务必填标题、`🛫` 和 `📅`。
2. canonical 父任务下新增 canonical 子任务，不带项目标签，备注用 blockquote。
3. 旧父任务下新增旧格式子任务，保留 `#project/项目名` 和原备注风格；不自动迁移整棵任务。
4. 删除子任务时删除其完整子树与备注，不只删除 checkbox 行。
5. canonical 任务树增删后按 `task-format.md` 重算父进度条（包含内联主题色）；删到没有子任务时移除进度条。
6. 合并任务前确认新标题、日期取值、备注合并顺序和原任务是否删除，不自行推断。

## 写后核验

- 重新读取目标文件，确认目标任务只命中一次且拟修改字段已生效。
- 核对任务树 checkbox 数量；结构修改除外时数量不得变化。
- 项目移动核对源分区不再包含目标树、目标分区完整包含目标树。
- canonical 父任务核对进度条段数等于直接子任务数，并逐段核对状态 class 与内联主题色一致。
